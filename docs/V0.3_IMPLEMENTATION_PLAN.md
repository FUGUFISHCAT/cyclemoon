# V0.3 实施计划与审查风险
## 顺序
1. 基线审查、隐私扫描和 Git 检查点（完成，a82a1c0）。
2. P0 数据控制器：草稿 revision、事务后成功、广播失败隔离、IDB 配额 / 升级保护；保留原数据协议。
3. P0 备份：新导出 schema 3 与旧格式兼容，测试无损恢复 / 拒绝非法数据。
4. P0 移动端：统一主题、320–430 布局、日历 44px、快速记录弹层、键盘与安全区域。
5. P0 SW：离线监听、外壳完整性、旧脚本回退、保守缓存清理；算法日期与不确定性修正。
6. P1：ICS 重复导出保护、数据清除、隐私说明。
7. 重新运行自动检查和生产构建；桌面四个宽度、实际 IDB、备份、离线与升级；生成 ZIP、六份交付文档和报告。iPhone / 公网部署保留为未验证。

## 风险与修复标准
| 风险 | V0.2 审查结果 | V0.3 修复 / 验证 |
| --- | --- | --- |
| R1 触控与键盘 | 日历在 320px 扣除双层 padding 后约 32px；表单长 | 日历专用紧凑容器、44px 网格；弹层与视口；四宽测量 |
| R2 陈旧草稿 | focus / 广播加载后 save 使用最新 revision，旧字段可能覆盖他人修改 | 草稿显式传入基准 revision，冲突保留草稿 |
| R3 误报保存失败 | 广播异常被当作 commit 失败 | 广播失败与事务结果分离并测试 |
| R4 备份合同 | schema2 data 内嵌，无 appVersion / 顶层要求字段 | schema3 导出 + schema1/2 读取，无内部库破坏性迁移 |
| R5 升级后旧脚本 | 保留旧缓存，但 fetch 只认新 ASSETS | 从本应用旧缓存读取旧哈希资源，测试旧页面升级 |
| R6 离线监听 | version 请求失败会跳过注册 / 更新监听 | 先绑定已有注册，离线也能显示状态，联网再检查 |
| R7 部署数据泄漏 | 主要按文件名筛查 | 静态资源白名单、文本内容扫描、ZIP 校验、明确无自动部署 |
| R8 清除与复活 | 无清除入口 | 空状态事务 + revision 递增 + 旧草稿冲突 + 明确输入确认 |
| R9 预测标签 | 进行中的后续日可能显示为实际经期；排卵窗口未随周期范围扩展 | 记录状态与估计分开，粗略窗口体现不确定性 |
| R10 迁移 / 配额 | 基础事务测试存在，缺乏实际失败注入 | 加入 quota / abort / 缺失仓库 / 未知版本保护 |
