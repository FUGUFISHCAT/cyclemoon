# 浏览器和新旧网址迁移

适用 V0.3.1；未执行生产迁移。Safari 标签页、主屏幕 PWA、不同浏览器/设备的数据可能隔离；改变域名或协议后 IndexedDB 不会自动同步。CloudBase 托管只负责应用文件，不接收健康备份。

1. **保留旧环境**：不要删除 Cloudflare 项目、旧图标或清理浏览器数据。记录旧网址和实际有记录的入口（Safari 或主屏幕），不要假设二者一样。
2. **导出旧数据**：在有记录的旧入口设置中导出 JSON。兼容设备优先调用系统文件分享；选择“存储到文件”，选你信任的位置，完成后打开“文件”App 确认有 JSON。取消分享表示未确认保存，不显示成功。若回退为下载，在 Safari 下载项找到文件并确认保存。JSON 未加密，避免公共链接、公开服务器或聊天转发。
3. **安装新空环境**：新网址 HTTPS、JS/图标、SW、离线虚构记录都验证后，先添加主屏幕，再在以后实际使用的新入口导入；不要先在 Safari 导入后假定主屏幕自动有数据。
4. **恢复前保护现有记录**：如果新环境已有记录，手动导出其备份。选择旧 JSON 后核对预览，经期/日志数量、参数、时间设置；输入“恢复”后才明确覆盖。恢复为整份替换、不合并。自动保护原数据是 V0.4 待办，本次未实现。
5. **完整性核对**：核对经期 ID 对应的日期区间、结束日期待确认状态、身体日志、中文/emoji/换行、周期参数、四类提醒开关与时间/隐私设置。刷新、关闭重开、离线新建测试记录再重开。导出新 JSON 与旧文件规范化比较，不能只比较文件字节（导出时间/应用版本会不同）。
6. **保留两份备份**：旧 JSON 和新环境回读导出的 JSON 分别保管，确认文件可再次选择与预览；验证完成之前绝不建议删除旧网站或清理旧浏览器。即使完成，也可继续保留旧站作为恢复入口。
7. **日历单独处理**：ICS 只是提醒副本，不是记录备份，不含完整症状与备注，不能用于恢复。新旧网站的 ICS 都不会自动更新已导入事件，重新导入前处理旧事件以免重复；私密标题仍会暴露时间，日历账户可能同步到云端。

V0.3.1 将数据库和 snapshot 协议升级到 v3，以保护 endPending（结束日期未知）状态；v1/v2 数据在原库内读取升级、保留 revision 和全部旧记录，不删除对象存储。旧版客户端不能降级打开 v3 数据库。不要在同源回滚到 V0.3.0 来修改新状态；应保留备份、使用兼容版本恢复。旧 JSON v1/v2/v3 仍可由 V0.3.1 校验导入，新状态应使用 V0.3.1 或更新兼容版本恢复。

### iPhone 真机清单（未验证）

- Safari 和主屏幕分别确认数据来源、存储隔离行为。
- JSON 和 ICS 文件分享，取消、不支持时下载回退，“存储到文件”后实际文件可打开。
- 主屏幕导入预览、覆盖确认、刷新、杀进程后数据仍在。
- 14 天核对、不确定日期、新经期、离线补填旧结束日期。
